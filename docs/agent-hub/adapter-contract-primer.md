# Adapter 契约：白话版

> 这是 [adapter-contract.md](./adapter-contract.md) 的白话讲解，为**第一次接触这个平台的人**而写。
> 正式契约是权威（authoritative）。两者冲突，以正式契约为准。
> 领域词汇以 [`CONTEXT.md`](../../CONTEXT.md) 为准。

## 1. 我们要解决的是什么问题

平台要能派活给各种编码 Agent：zcode、bash、codex、claude。这些人脾气完全不同：

- 有的能记住上次聊到哪，有的完全没有记忆；
- 有的说话带口音（输出格式不一样），有的只会干完喊一声；
- 有的能中途被打断，有的杀了它还有孙进程在跑。

如果平台为每一个人写一套对接代码，那么**来一个新 Agent 就要改平台**。我们要的不是这个。

我们要的是：**平台说自己的语言，每个 Agent 自带一个翻译。换 Agent，平台一行不改。**

那份「平台和翻译之间的约定」，就是 Adapter 契约。

### 打比方

你是公司**前台**（平台）。你把活派给不同的人（Agent）。

- 老张说话带口音，小李不会写字只能喊，老王记性差。——这是**翻译（Adapter）**的事。
- 活单长什么样、回执长什么样、谁负责记编号、谁负责算时间——这是**前台与翻译之间的约定**，也就是契约。

## 3. 谁干什么（第一个问题）

| | 引擎 | Adapter |
| --- | --- | --- |
| 起进程、收日志、写文件 | ✅ | ❌ |
| 算时间、决定怎么杀 | ✅ | ❌ |
| 结算任务、保管句柄 | ✅ | ❌ |
| 把活单翻译成那个人听得懂的话 | ❌ | ✅ |
| 把那个人的吆喝翻译成事件 | ❌ | ✅ |
| 报告自己会什么、不会什么 | ❌ | ✅ |

**为什么这么分**：翻译错了，是 Adapter 的锅；机器故障，是引擎的锅。出了事知道找谁。

**三条纪律**：

1. Adapter 是**纯翻译**——不自己起进程、不自己写日志、不自己碰磁盘。
2. Adapter **不许偷偷攒全局状态**。将来若要复用常驻服务，那个池子归引擎管。
3. 接口上只露出正式契约第 2 节列的那些成员，实现细节留给实现。

## 4. 一次派活的全过程

```
  平台                          引擎                        Adapter               Agent
   │                             │                            │                    │
   │ ① 派活（活单）               │                            │                    │
   ├────────────────────────────►│                            │                    │
   │                             │ ② 先问：你行吗？            │                    │
   │                             ├───────────────────────────►│                    │
   │                             │   能力 / 权限可强制？句柄归属？│                    │
   │                             │◄───────────────────────────┤                    │
   │                             │   不行 → 当场拒绝并说清缺什么  │                    │
   │                             │                            │ ③ 翻成那个人的叫法   │
   │                             │                            ├───────────────────►│
   │                             │ ④ 起进程、收日志（引擎的活） │                    │
   │                             │◄───────────────────────────┴────────────────────┤
   │                             │      原始输出（口音）        │                    │
   │                             │ ⑤ 交给 Adapter 翻译         │                    │
   │                             │◄───────────────────────────┤                    │
   │                             │      归一事件序列            │                    │
   │ ⑥ 事件推进看板               │                            │                    │
   │◄────────────────────────────┤                            │                    │
   │                             │      最后一条：结论 Resolution│                    │
   │ ⑦ 结算 Task                 │                            │                    │
   │◄────────────────────────────┤                            │                    │
```

**图里的两个关键点**：

- **第 ② 步在最前面。** 能力不对，当场拒绝——绝不「先跑跑看」。
- **第 ⑤ 步是纯函数。** 同一份原始输出，永远翻译出同一串事件。这让它可以用假数据直接测。

## 5. 第二个问题：这个人能干什么

每个 Adapter 上岗前**先自报家门**：

| 报什么 | 白话 |
| --- | --- |
| `resume` | 我能不能记住上次会话 |
| `termination` | 我被打断时，能不能把整棵进程树都带走 |
| `streaming` | 我是不是边说边干（还是干完才吭声） |
| `sessionReadback` | 我能不能读回自己的聊天记录（v1 只登记，不做） |
| `enforceable` | 你给我定的规矩，我**保证得了**哪几条 |

**平台不相信、不试探、不临时凑合。** 你要的活超出他报的能力，平台**当场拒绝并说清缺哪一条**。

> 反面教材在现有代码里：有个 Adapter 在找不到真 CLI 时，**偷偷换成一个假 CLI 并当作可用**（`src/adapters/zcode.ts:21-22`）。在新契约下这必须是 `ok: false`，理由「CLI not found」。凑合跑的结果是「看起来成功了，其实是假的」——比直接失败坏得多。

## 6. 第三个问题：派活时给什么

**必填三样**：

| 字段 | 白话 |
| --- | --- |
| `taskId` | 编号。**平台起**，Adapter 不许自己命名 |
| `instructions` | 要干什么 |
| `workspace` | 在哪个目录干 |

**可选三样**：`sessionRef`（上次会话的把手）、`permission`（权限要求）、`adapterEnv`（环境变量增量）。

**活单里永远没有的**：

- **时间上限**——只有平台知道队列多长、总共允许多少活同时在跑、重启接管窗口多大。某个 Adapter 拿不到这个信息，就不该替平台做主。
- **任何命令行旗标**——那是那个人的方言。写进活单，等于把一个人的口音刻在前台墙上。
- **任何进程号**——那会把「一个任务一个进程」焊死成契约条款，将来想换成常驻服务就得改接口。

### 权限怎么定

不说「用哪个 CLI 的模式」，改说**四个维度**：能不能写文件、能不能跑命令、能不能联网、需要批准时怎么办。

还有一个**强制拒绝条款**，这是全场最硬的一条：

> Adapter 必须报**它能强制哪几维**。你要求的那一维它保证不了，`dispatch` **当场拒绝**——绝不许「收下要求，然后照样放开跑」。

现实例子：某个 CLI 只能整体移除工具、不支持按命令模式匹配。那它对「禁止执行命令」就是**不可强制**——它必须报 `enforceable: []`，而不是假装限制了。

## 7. 第四个问题：干完回什么

回执是一串**事件**，最后一条必须是**结论**。结论只有一个词：

| 结论 | 白话 |
| --- | --- |
| `succeeded` | 干成了 |
| `failed` | 没干成 |
| `needs_review` | 干完了，但**看不出成没成**，得人来瞅一眼 |

**结论只能由翻译给**，引擎不许自己猜语义。但有两种情况引擎直接盖过翻译：**超时**和**被取消**——因为那是平台自己发起的，不是那个人的表态。

### 三条边界（都不许含糊）

| 情形 | 判定 | 为什么 |
| --- | --- | --- |
| 退出码 0，但一个字没说 | **成功**，并显式标记「空输出」 | 这是确定性事实，不是看不懂。算不算成功由翻译决定 |
| 进程压根没起来 | **失败** | 确定性失败，不是「无法判定」 |
| 有输出，但读不懂成没成 | **`needs_review`** | `needs_review` 唯一的用途就是这一条 |

**为什么这条重要**：`needs_review` 是**给人加班的信号**。乱用它，人就会被没事找事地叫起来看。

## 8. 会话那件事（最绕，单独讲）

「会话」就是跟同一个 Agent 的长期对话通道。平台需要一个**把手**，下次才能接着聊。

```
   第一次派活                     第二次派活
   ┌──────────┐                  ┌──────────┐
   │ 无把手    │ ── 新建会话 ──►  │ 有把手    │ ── 续跑 ──► 接着聊
   └──────────┘                  └──────────┘
        │                              ▲
        └── Agent 报了把手 ────────────┘
```

四条规矩：

1. 把手**长什么样，平台不知道也不许知道**（不解析、不假设前缀）。
2. 把手**由平台保管**，不是 Adapter 记在自己本子上。
3. 有的 Agent 允许前台**提前指定**把手，它就报「不需要提取」。
4. 有的 Agent 只把把手混在输出里，Adapter 用一个**独立的小函数**把它抠出来。

### 抠不到怎么办

这是我们争得最值的一条，也是唯一一处我改了票面选项的地方：

> **抠不到 ≠ 任务失败。** 活干完了、答案拿到了，只是下次接不上话。

所以：

- **任务照常结算**（成功就是成功）。
- **会话被标成「续跑能力降级」**，下次派活前要人点一下头。

如果 Adapter 压根没有会话能力（比如 bash），那从建会话起就知道，不算降级。

如果 Adapter 说「我有会话能力」，但会话在 Agent 那边被删了 → 下次续跑必然失败。平台**只把这次失败记清楚，不自动新建会话**（静默换会话会把「续跑失败」伪装成「正常续跑」）。

## 9. 谁不许出现在契约里

这是「换 Agent 不改平台」的**唯一执行手段**。

| 禁 | 现成的违规（就在本仓库） |
| --- | --- |
| 任何 CLI 的旗标名 | `src/adapters/zcode.ts:36-45`（实现层允许，爬上接口即违规） |
| 任何 CLI 的输出字段名 | `src/cli.ts:81-92` |
| 磁盘路径 / 目录约定 | `src/adapters/zcode.ts:8,21-22` 把测试替身路径内嵌 |
| 权限模式字面量（`edit`/`yolo`/`build`/`plan`） | **`src/adapters/base.ts:9`** |
| 进程原语（`pid`/`kill`/`spawn`/`signal`/`exit code`） | `src/adapters/base.ts:15-19` |
| 时间预算（`timeout`） | **`src/adapters/base.ts:12`** |

**允许的词汇**：Task / Session / Dispatch / Chain / Actor / Board / needs_review，以及契约自己定义的中立成员名。

## 11. 白纸黑字：这份契约长什么样

正式契约（[adapter-contract.md](./adapter-contract.md)）给出 TypeScript 形态。这里只列成员的**白话职责**：

| 成员 | 白话 |
| --- | --- |
| `name` | 我叫什么（也用来标记句柄是谁给的） |
| `contractVersion` | 我按哪版契约写的（平台只记日志，不拒绝） |
| `capabilities` | 我会什么、不会什么（静态声明，一次说清） |
| `defaultPermission` | 平台没特别交代时，我默认怎么办 |
| `available()` | 我现在能不能用（探不到就说清为什么） |
| `dispatch(spec)` | 派活。返回一个**运行句柄** |
| `sessionRefOf(raw)` | 从原始输出里抠出会话把手（纯函数） |
| `dispose?()` | 释放我 |

运行句柄里有四样：`taskId`、事件流 `events`、取消 `cancel()`、结论 `done`。

**为什么 `cancel()` 绑在句柄上**：靠任务编号回查，会逼着 Adapter 维护一张全局活动表——那是跨派发的隐式状态，正是我们要禁的。

## 12. 怎么证明这份契约是干净的

用一个**最笨的 Agent** —— bash：没有会话、不会记忆、只能杀主进程、什么用量都拿不到 —— 写一份样例。它必须自证 9 条（详见正式契约第 7.1 节）：

1. 契约里没有旗标名 / 输出字段名 / 磁盘路径
2. 翻译是纯函数、零副作用
3. 能诚实说「我没有 resume、不能读回会话库」
4. 「做不到」的声明机制真的能被触发
5. 抠不到把手时，降级路径真的走得到
6. 新建与续跑在同一意图里走两条分支
7. 空输出与「起不来」走两条不同判定
8. 不替换整个环境，只给增量
9. 执行目录由活单传入，Adapter 不自己推断

**如果 bash 用起来别扭，说明契约里混进了聪明 Agent 的特性。**
