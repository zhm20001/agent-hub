# 统一整理任务查询

**背景：** 2026-10-15 架构复评后，用户授权自主设计、依次修正五项，每完成一项单独 jj 提交。平台只记录机械事实，不判定任务内容是否成功。

## 方案

- 新增任务查询模块负责修复、补全、持久化和一致的数据拼装；HTTP 只校验参数、映射状态码并返回结果。
- 详情、对话、原文定位、工具查询共享逻辑；任务列表扫描走存储。
- 日志尾部限量读取；保留现有响应字段、归档过滤、无对话时的说明。

## 修改范围

- `src/runner/task-queries.ts`
- `src/server.ts`
- `src/tools.ts`
- `tests/task-queries.spec.ts`

## 验收

- [ ] 缺失/运行中/正常结束/被取消/孤儿任务查询符合原有约定。
- [ ] 详情最后回复与对话一致；单独缺失模型或 provider 也能补全。
- [ ] HTTP 与工具共用查询；查询无任务返回 null；大日志只读取尾部。

## 执行步骤

- [ ] 先添加能复现问题的行为测试并确认失败。
- [ ] 完成实现，运行针对性测试。
- [ ] 运行 `npm test` 和 `npm run build`，检查改动范围。
- [ ] 更新此文档的状态、验证结果，使用 `jj commit <本项文件> -m "..."` 单独提交。

## 约束

- 保留原有其他工单，不纳入本次提交。
- 沿用现有目录和 HTTP 返回格式；不引入消息队列、通用插件框架或数据库。
- 测试使用假 CLI 和临时数据，不调用付费 Agent，不执行真实编码任务。
