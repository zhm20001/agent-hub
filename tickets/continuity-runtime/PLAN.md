# AgentHub：可靠派发与项目接续

目标：保留 Agent 派发核心，让人和主 Agent 在离开数日后能找回目标、已知事实和下一步。参考本地 Orchestrate 源码，而非照搬其云端工作流。

## 决策

- 一个 Hub 实例集中创建存储、任务执行器、查询和项目记录；HTTP 与 Agent 工具共享它，保留旧函数兼容入口。
- SQLite 保存任务状态、请求登记、事件和读取位置。日志、报告、原始对话继续是文件；数据库事务不能替代进程启动/退出恢复协议。
- request_key 相同且请求相同返回原任务；相同 key 不同内容报冲突。启动结果不明时不擅自重启进程。
- 项目记录目标；追加接续笔记，笔记不能悄悄覆盖目标。看板仅显示项目、关联任务、最新笔记及上次已读后的事实变化。
- 任务 handoff 是带来源的 Agent 自述，不是平台的成功裁决。仅文本 Agent 可接收有界上游/项目资料；Bash 命令保持原样。
- 批量派发先完整校验，再执行；不新增自动规划器，不执行交接中建议的验证命令，不在运行中并发 resume 同一 session。

## 实施顺序与验收

1. **运行实例与存储**：显式实例、SQLite/旧文件导入、请求去重。验证跨实例隔离、重启与并发去重、冲突、原有恢复测试。
2. **交接与工单**：可选结构交接、有界依赖资料、模板单次替换、整批校验与稳定请求键。验证错误结构/异常结束/缺失依赖/Bash 不变/派发前拒绝非法集合。
3. **项目接续与统一入口**：项目和追加笔记、读取位置，接入 HTTP、Agent 工具和轻量看板。验证重启后记录保留、读取不自动已读、项目隔离和端到端派发。
4. **交付可靠性**：持久通知位置和失败重试、SSE 游标/UTF-8/重连、明确宿主通知目标、可安装构建。验证关闭和失败回滚、日志尾部不丢、构建产物可启动。
5. **收口**：独立审查、全套测试与构建；更新架构文档、用法和本工单状态。每个可验证阶段单独提交，保留原有未提交工单。

### 借鉴与取舍

Orchestrate 的 `core/handoff.ts`、`core/prompts.ts` 和 `schemas.ts` 提供了交接资料、上游上下文、整批依赖校验的启发。这里加入严格结构检查、来源、长度边界和 Bash 例外；没有照搬云端时限或自动 verifier 裁决。项目接续保持为目标、追加笔记、相关任务与已读位置，不引入重型流程平台。

SQLite 事务只保护数据库内的记录；启动外部进程仍由已有 PID 登记与退出证据协议保护。通知为至少一次，需要接收方去重；同一消费者应只有一个活跃投递者。Agent 的交接始终是有来源的自述。
